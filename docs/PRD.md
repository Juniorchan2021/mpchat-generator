## 1. 功能 1：长文多语言一键翻译

### 1.1 用户故事

**作为**内容运营人员，**我想要**将生成或优化后的中文/英文文章一键翻译为其他语言，**以便**快速覆盖多语言市场而无需手动翻译。

### 1.2 功能范围

| 项目 | 描述 |
|------|------|
| 入口位置 | 软文工作台（文章预览下方）+ 外部文章页面（优化结果下方） |
| 支持语言 | 简体中文 ↔ 英文、简体中文 → 繁体中文（初期），后续可扩展至全部 16 种语言 |
| 核心要求 | 保持 Markdown 格式不变（标题层级、列表、链接、代码块、图片引用） |

### 1.3 用户流程

1. 用户在工作台生成文章，或在外部文章页面完成优化
2. 文章预览区域下方出现翻译按钮组（「翻译为英文」「翻译为繁体中文」）
3. 点击按钮后显示 loading 状态
4. 翻译完成后在折叠面板中展示翻译结果
5. 用户可复制/导出翻译后的文章

### 1.4 验收标准

- [ ] AC-1：点击「翻译为英文」后，中文 Markdown 文章翻译为英文，H1-H4、列表、链接格式完整保留
- [ ] AC-2：翻译过程中显示 loading 状态，不可重复触发
- [ ] AC-3：翻译结果可以通过「复制」「导出 Markdown」操作保存
- [ ] AC-4：翻译失败时显示有意义的错误提示
- [ ] AC-5：外部文章页面同样支持翻译功能

### 1.5 优先级

**P1** — 改动最小，复用现有 LLM 管道，价值高

## 2. 功能 2：SEO 批量选题助手

### 2.1 用户故事

**作为**内容运营人员，**我想要**输入一个核心关键词就能获得 20-50 个 SEO 爆款标题建议，**以便**快速规划内容日历并提升关键词覆盖率。

### 2.2 功能范围

| 项目 | 描述 |
|------|------|
| 独立页面 | `/ideation` 选题助手页面 |
| 工作台集成 | 关键词输入框旁增加「AI 选题」快捷按钮 |
| 输出格式 | 每个标题含搜索意图、SEO 难度、相关关键词 |

### 2.3 用户流程

#### 独立页面

1. 用户进入 `/ideation` 页面
2. 输入核心关键词（必填）和行业领域（可选）
3. 调整生成数量（20-50 滑块，默认 30）
4. 点击「生成选题」
5. 展示标题列表，每行显示搜索意图标签和难度星级
6. 用户点击「使用此标题」→ 跳转到工作台，关键词和场景自动填入

#### 工作台快捷入口

1. 用户在工作台关键词输入框旁点击「AI 选题」
2. 弹出迷你选题面板（Popover）
3. 选中标题后自动填入关键词字段并关闭面板

### 2.4 验收标准

- [ ] AC-1：输入关键词后 30 秒内返回 20-50 个标题建议
- [ ] AC-2：每个标题包含 `title`, `search_intent`, `difficulty`, `keywords` 四个字段
- [ ] AC-3：独立页面点击「使用此标题」能跳转到工作台并自动填入
- [ ] AC-4：工作台迷你面板可弹出/关闭，选中后正确填入关键词
- [ ] AC-5：导航栏显示「选题」入口

### 2.5 优先级

**P2** — 新页面开发，内容运营高频需求

## 3. 功能 3：扩展长文发布渠道

### 3.1 用户故事

**作为**内容运营人员，**我想要**将生成的文章直接发布到 Paragraph（Web3 博客）和 Medium，**以便**扩大内容分发范围而无需手动复制粘贴。

### 3.2 功能范围

| 项目 | 描述 |
|------|------|
| 新增平台 | Paragraph（API 直发）、Medium（API 直发，升级现有格式预览） |
| 新增入口 | 外部文章页面增加发布面板（当前仅工作台有） |
| 兼容性 | 保留现有 Dev.to、Hashnode 直发及其他平台格式预览 |

### 3.3 用户流程

1. 用户在工作台生成文章或在外部文章页面优化文章
2. 在发布面板选择目标平台
3. 对于 Paragraph/Medium：输入 API Token → 点击发布 → 返回文章 URL
4. 对于其他平台：保持现有格式预览/直发行为

### 3.4 验收标准

- [ ] AC-1：Paragraph 发布成功后返回文章 URL
- [ ] AC-2：Medium 通过 API 直发 draft/public 文章
- [ ] AC-3：Medium 无 token 时降级为格式预览（向后兼容）
- [ ] AC-4：外部文章页面新增发布面板，支持全部平台
- [ ] AC-5：外部文章页面发布时需提供标题输入框

### 3.5 优先级

**P1** — 直接提升分发效率，后端改动集中

## 4. 功能 4：Intercom QA 帮助中心生成

### 4.1 用户故事

**作为**产品经理/客服团队，**我想要**输入产品功能点描述就能自动生成标准化 QA 文档并上传到 Intercom 帮助中心，**以便**快速构建和更新产品帮助文档。

### 4.2 功能范围

| 项目 | 描述 |
|------|------|
| 独立页面 | `/intercom-qa` |
| AI 生成 | 输入功能描述 → 输出结构化 QA 列表 |
| 编辑能力 | 逐项编辑 question/answer |
| 导出 | 支持 Markdown 和 JSON 格式导出 |
| Intercom 上传 | 通过 Help Center API 直接上传到指定 Collection |

### 4.3 用户流程

1. 用户进入 `/intercom-qa` 页面
2. 输入产品功能描述（多行文本）、产品名、语气风格
3. 调整生成数量（5-20，默认 10）
4. 点击「生成 QA」
5. 展示 QA 卡片列表，每项含 question、answer、category
6. 用户可逐项编辑内容
7. 点击「导出 Markdown」或「导出 JSON」保存
8. 输入 Intercom Token + Collection ID 后点击「上传到 Intercom」

### 4.4 验收标准

- [ ] AC-1：输入功能描述后生成 5-20 个 QA 对
- [ ] AC-2：每个 QA 含 `question`, `answer`, `category` 三个字段
- [ ] AC-3：QA 列表每项可在线编辑
- [ ] AC-4：导出 Markdown 格式为 `## Q: ...` + `A: ...`
- [ ] AC-5：导出 JSON 格式为标准数组
- [ ] AC-6：Intercom 上传成功时显示确认，失败时显示错误
- [ ] AC-7：导航栏显示「QA 生成」入口

### 4.5 优先级

**P2** — 独立功能，含外部 API 集成，可与其他功能并行开发

## 5. 优先级排序

| 排名 | 功能 | 优先级 | 理由 |
|------|------|--------|------|
| 1 | 长文多语言翻译 | P1 | 改动最小，复用现有管道，多语言内容是核心需求 |
| 2 | 扩展发布渠道 | P1 | 直接提升分发效率，用户日常高频操作 |
| 3 | SEO 批量选题 | P2 | 新页面开发，提升内容规划效率 |
| 4 | Intercom QA | P2 | 独立模块，面向不同用户角色 |

---

## 6. 非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 翻译/选题/QA 生成单次请求 < 60 秒 |
| 兼容性 | 新功能不影响现有软文生成、外部文章优化等核心流程 |
| 国际化 | 所有新增 UI 文案提供中文 + 英文 |
| 错误处理 | API 调用失败时前端显示用户友好的错误信息 |
| 安全 | API Token 仅在请求时传输，不持久化到后端 |
